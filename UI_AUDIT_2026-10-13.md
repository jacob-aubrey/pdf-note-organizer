# Notable Interface Audit

October 13, 2026. Source application audit and implementation.

## Scope

Reviewed Inbox, Library, Notes, reMarkable, expanded cloud setup, all four
Settings pages, advanced processing controls, Folder settings, Search options,
citations and citation conflict review, supplementary files, tags and
collections, saved searches, duplicate review, transfers, pairing, annotation
history, Help, storage maintenance, recovery archives, extra-PDF cleanup,
drawing enlargement and full-page context.

The visual fixture uses disposable PDFs, annotations, folders and an offline
tablet catalog. Background services and online identification are not started.
Screenshots and geometry reports are generated locally under
`tmp/qa/pristine/`. No executable is built by this audit.

## Findings and Changes

| Area | Finding | Implemented change |
| --- | --- | --- |
| Folder settings | Processing explanations and the example shared grid rows with footer controls. | Give explanations, the preview and footer separate rows. |
| Settings | Only Sorting scrolled; other pages could lose content when height was restricted. | Use the same scrollable form on every page. Save and Cancel remain outside the scrolling area. |
| Keyboard navigation | Tabbing into a long form could focus a control below the viewport. | Scroll the focused control into view. |
| Path controls | Wide entry requests could squeeze copy and browse buttons to zero width. | Let paths use the remaining width; reserve their actions and retain complete-value hover help. |
| Inbox | Long absolute paths consumed several lines of workspace height. | Put Inbox and Library locations in matching read-only path fields with copy actions. Keep counts and processing status separate. |
| Inbox | Review actions clipped in a narrow pane; filename editing could run below the window. | Wrap review actions and scroll the filename/destination form. |
| Main action rows | Button rectangles could fit while their labels were clipped. | Wrap Inbox, paper, Notes and cloud actions using measured requested widths. |
| Cloud utilities | A long command strip reduced the space for review tables. | Use icon buttons for the transfer queue and connection menu, with action labels retained and contextual tooltips. |
| Cloud mapping | Two labeled commands stacked in short, narrow mapping panes. | Use the same commands as compact icon buttons when space is limited. |
| Cloud setup | Copy actions could disappear beside source/destination fields. | Allow fields to shrink; use a compact inline Apply action in narrow setup layouts. |
| Library details | Full detail panels could consume the room needed for table rows. | Short panes condense to the location selector and path-copy action. Full explanations and Copy details return when the pane is taller; table hover help remains available. |
| Processing log | An expanded log could push table rows out of a short workspace. | Reduce the log height and padding in short windows; retain its scrollbar and location-copy controls. |
| Library | A permanent explanatory paragraph reduced useful reading space. | Keep workflow guidance in Help and contextual tooltips. |
| Search | The search entry could consume space needed by the scope/options controls. | Reserve fixed controls before allocating the entry's remaining width. |
| Supplementary files | Tables could squeeze the bottom commands out of a height-limited window. | Allocate fixed controls first and share the remaining height between the two tables. Action rows wrap. |
| Supplementary files | A separate table implementation lacked the common overflow and column-sizing behavior. | Use the shared table component, scrollbars, cell tooltips and column controls. |
| Empty tables | Blank tables gave no indication of their state. | Show muted empty-state text without inserting a selectable placeholder row. |
| Saved searches | No visible Close command or scrollbar; actions appeared available before loading/selection. | Add Close, scrolling, wrapping actions, loading/selection states and selection retention after saving. |
| Tags and collections | No visible way to discard the draft other than closing the window. | Add Cancel using the existing guarded close behavior. |
| Dialog actions | Settings placed its primary action on the opposite side of Cancel from other editors. | Use Cancel immediately left of the primary confirmation. |
| Reading | Title, page metadata and note content had the same visual weight. | Give the paper title and page metadata distinct typography and add restrained paragraph spacing. |
| Counts | Singular results displayed as "1 notes" and "1 results". | Use singular/plural counts consistently in Notes, Inbox and saved searches. |
| Theme | Context menus, saved-search lists, radio buttons and progress bars had incomplete shared styling. | Centralize colors, typography, selection, disabled and focus states. |
| DPI | Table row height stayed fixed while fonts grew. | Derive the minimum row height from actual font metrics, including checks through 200% scaling. |
| Context actions | Text/image context menus omitted the icon used for the same action elsewhere. | Use the bundled Copy icon and shared menu styling. |
| Maintenance | Open restored library appeared below Close. | Put the recovery action and Close together in the reserved footer. |
| Deferred layouts | Cancelling child-owned idle callbacks during root teardown could leave stale Tcl command references. | Own toolbar idle callbacks on the root and cancel them when the toolbar is destroyed. |
| Image viewers | Image creation depended on Tk's implicit default root. | Explicitly bind viewer images to their canvas interpreter. |
| App identity | The old app icon differed from the interface's icon family and source previews did not install it. | Install the Notable icon centrally for main/child windows, with an explicit Windows taskbar identity. |

## Application Icon

Selected [Lucide notebook-pen](https://lucide.dev/icons/notebook-pen), under the
[ISC license](https://lucide.dev/license). A white notebook and pen sit on a
solid Notable blue tile. It matches the existing locally bundled Lucide icons
and communicates reading, annotation and writing without lettering or fine
decorative detail.

The original SVG is pinned to Lucide revision
`f12b0de177fbc2a6795e99be065887e72b237123`. The copyright and license notices
remain in `note_organizer/assets/icons/LICENSE.txt`; adaptation provenance is
in `note_organizer/assets/branding/SOURCE.txt`.

`Note icon.ico` contains 16, 20, 24, 32, 40, 48, 64, 128 and 256-pixel images.
The source app uses this bundle for Windows title bars and taskbar identity.
Child windows inherit the default icon. PNG variants support Tk icon-photo
handling. The existing packaging specification includes the new assets for
future builds.

Regenerate entirely from local assets:

```powershell
.\.venv\Scripts\python.exe scripts/build_app_icon.py
```

## Verification

Final results:

- **180 screenshots:** 30 workspace/dialog states at each of six size/scaling
  combinations. Final geometry reports contain zero findings and zero Tk
  callback errors. The smallest view also keeps complete table rows visible
  with selected cloud items, expanded setup and the processing log open.
- **Full regression run:** 864 cases completed; 863 passed. One test still
  assumed the original Inbox editor's exact parent nesting. It was updated to
  find the containing split pane through the new scroll container, retaining
  its compact-path, full-value tooltip and clipboard assertions.
- **Final focused rerun:** all 37 path-visibility, new interface-audit and
  existing UI-polish cases passed, including that corrected structural test.
  Every case in the full run has therefore passed across the full and focused
  runs. The full suite was not repeated after this test-only correction and
  the final small spacing, tooltip and Windows icon-assignment refinements.
- Both branding/theme checks passed again after the Windows refinement. A
  live desktop preview verified the new notebook-and-pen title-bar icon;
  Windows needs the current window's bitmap assigned explicitly as well as
  registering the default for future windows.
- Source compilation, dependency validation (`pip check`) and whitespace
  validation (`git diff --check`) passed.

The repeatable visual audit captures both 940x620 and 1250x820 windows at
100%, 125% and 150% Tk scaling. It checks button label widths, missing
controls, overlapping controls, table reading space and Tk callback errors.
Inactive notebook pages and intentionally hidden controls are excluded.
Screenshots are additionally inspected for layout and actual PDF rendering.

```powershell
.\.venv\Scripts\python.exe -m tests.qa_pristine --capture --scale 1.5 --small
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m compileall -q note_organizer tests scripts
git diff --check
```

New regression coverage checks Settings scrolling and keyboard focus, footer
visibility, Folder settings row separation, empty-state transitions, menu/list
styling, supplementary-file controls at restricted height, toolbar visibility
and teardown, font-aware row sizing and all nine ICO resolutions.

This is a bounded desktop audit, not certification for every Windows theme,
monitor arrangement or assistive technology. Native file/confirmation dialogs
continue to follow Windows styling. The existing source launcher opens the
updated application; a running instance needs a restart to load these changes.
