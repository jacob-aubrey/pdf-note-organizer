# Plugin interface and update compatibility

## Scope and reuse

The user approved **reMarkable Sync for Zotero** as the display name and asked
for a broad UI repair after a screenshot showed folder-menu text painting over
the workspace. Version 0.3.1 refines the Zotero interface; it does not replace
the sync engine or the desktop application.

Reuse the application's bundled Lucide SVG icons (ISC; Feather-derived portions
retain their MIT attribution) and their existing source revision. These are
resolution-independent assets; CSS masks use the button's foreground color in
both themes. No additional icon dependency, service, runtime or recurring setup
is introduced. Licenses and source attribution are included in the XPI.

Reuse **installed Gecko native popup styling**, as Zotero's own windows do.
Inspection of Zotero 10.0.6's `omni.ja` confirmed that its preferences and note
windows load `chrome://global/skin/global.css` (or its directory alias). Our
workspace omitted this stylesheet. A real native HTML-select popup in the old
package had `appearance: none`; the repaired popup has native appearance and
bounded scrolling. The test opens a 120-option menu, selects an actual menu
item, closes it and repeats for all three setup selectors. Closed-select
screenshots alone cannot verify a native popup, which is a separate surface.

This uses the existing installed Zotero/Gecko runtime rather than copying its
source. Zotero is AGPL-3.0-or-later; Gecko's inspected CSS carries MPL-2.0.
The actual Windows Zotero 10.0.6 runtime is the compatibility target. No new
third-party control library or speculative cross-version compatibility is claimed.

Primary references cross-checked:

- https://www.zotero.org/support/dev/zotero_7_for_developers
- https://www.zotero.org/support/dev/zotero_10_for_developers
- https://github.com/lucide-icons/lucide

## Changes

- All ordinary buttons use shared wrapping action rows with a 10px gap. The
  navigation, review list and tag chips keep their own explicit layouts.
- Setup has separate connection, folder-scope and intake/search sections.
  Checkbox labels sit beside their controls; the pairing code has a bounded
  width. The save label explicitly says that it also starts synchronization.
- Icon labels remain readable and keyboard-accessible. Decorative icons are
  hidden from accessibility APIs. Destructive actions have a separate text
  color; selected review documents have a visible state.
- Header actions wrap. Review columns can shrink, and narrow windows switch to
  a single column. Long paper titles, button labels and tag chips wrap.
- Native popup styling is loaded at the window level. The native appearance of
  HTML selectors is explicitly retained after loading Gecko's chrome styling.
- Stylesheet and workspace-script URLs carry the release version. An actual
  in-place upgrade exposed cached old CSS: new JavaScript rendered new sections,
  but icons, checkbox rows and the pairing width retained their old appearance.
  Versioned URLs repaired the interface without restarting Zotero. Future
  releases must update these resource-version strings along with the manifest.

## Data compatibility

The extension ID `notable-companion@local.invalid`, `notable` profile directory,
API paths, database formats, stable key namespaces and attachment-ownership
markers retain their original names. Renaming those would be a data migration,
not a display-name change. The XPI's worker and runtime manifest are byte-for-byte
identical to 0.3.0. Install/uninstall hooks perform no library deletion.

In a disposable Zotero profile, upgrading from the old package retained the
native library catalog, all 11 attachment-file hashes, configuration, encrypted
Zotero grant, encrypted synthetic tablet token, two saved document links and
page-tag records. The synthetic token was never used for a cloud request. No
production library, pairing state or tablet document was used for this test.

Users should finish the current sync/import before replacing the plugin. Plugin
replacement closes its window and stops its helper temporarily. These results
establish compatibility for this interface release; future schema or sync
changes require their own migration checks. The preview has no published
automatic-update feed.

## Validation

The packaged workflow and populated UI checks run against disposable Zotero
10.0.6 profiles. `tools/test_zotero_plugin_ui.py` audits all five tabs in light
and dark themes at 1040px, plus dark mode at 640px. It expands secondary settings,
checks button intersections, horizontal overflow, native select bounds, icon
styling and checkbox layout, and records native-window screenshots for visual
inspection. The folder-menu interaction checks use 120 options per selector.

The strengthened checks include expanded naming templates, rename/move controls,
citation and recovery details. No real reMarkable account is accessed. Native
workflow checks use an in-memory cloud and actual Zotero attachments. OCR was
not rerun for the UI-only release; its packaged runtime bytes are unchanged.

Final results: **22 packaged workflow checks**, **18 populated UI/native-menu
checks**, and **5 upgrade-preservation comparisons** passed. The release is
`dist/reMarkable-Sync-for-Zotero-0.3.1.xpi`, SHA-256
`4603b5e4ca0c55c5897e52888748f58f5df8a4f04f97fe7d04e5cd74ce6b440b`.
The release metadata, guide, notices and two UI previews are alongside it.

The first four-paper bulk fixture was too small for the acceptance tool's final
three-file subset after three papers had already been filed. That assertion was
resolved by using eight synthetic papers, without changing application behavior.

Evidence directories (ignored, local only):

- `.test-tmp/zotero-ui-audit-04`: initial packaged workflow and UI checks.
- `.test-tmp/zotero-ui-upgrade-01`: upgrade-state comparison, native menu
  comparison and verification of the stylesheet cache repair.
- `.test-tmp/zotero-ui-final-01`: final package and expanded UI audit.

At the user's request, Tags, Add tag and the reader page-tag control now use
Lucide's actual `tag.svg`, retrieved from the same pinned revision and covered
by the bundled ISC notice. The release version and resource-cache query strings
advance to 0.3.2. JavaScript syntax, SVG XML and packaged icon references were
verified; the worker and runtime manifest remain identical to 0.3.1. This
cosmetic follow-up did not rerun the native workflow suite. Package checksum
