## Defects and boundaries found by testing

1. **Erased-stroke compatibility.** The first real-source sample passed 10 of 12 PDFs. Two contained parsed compressed tombstones; ignoring them could resurrect erased strokes. The renderer now adapts upstream-parsed ID runs before tree construction, preserving ordering and hiding erased marks. After regression tests, all 28 eligible real cached annotated PDFs rendered. Unknown payloads remain rejected.
2. **Native versus embedded annotations.** `/children` returned no annotation records. Explicit annotation-item retrieval returned embedded annotations too, but omitted their external/native flag. An initial pure-client guard therefore stopped legitimate refresh. The thin extension now checks Zotero's native flag and reuses its importer; independent desktop annotations blocked replacement in the real app test.
3. **External ink is not a native Zotero note.** The PDF retained its Ink object, but Zotero's importer created native external highlight/sticky-note objects only. The fixture was corrected to record this actual boundary rather than assert unsupported ink conversion. This is consistent with [the Zotero team's explanation](https://forums.zotero.org/discussion/126434/import-annotations-doesnt-work-for-freehand-markup-and-text-notes).
4. **Ordinary paper opening.** Zotero normally prefers its oldest matching PDF, which would select the retained original. The support extension now substitutes that source's explicitly linked tablet view. It preserves the original choice of main versus other PDFs instead of guessing from filenames.
5. **Index and reader recovery are separate.** Upload confirmation, native reader refresh and fulltext writes have independent retry state. A missing generated render can be rebuilt from retained sources. A later native PDF-only index rebuild is detected and the saved annotation/transcript text is restored.
6. **Transient Windows file locks.** A broad test run encountered Windows access-denied during metadata rename. A bounded retry now repeats the same atomic rename and leaves the old complete file on persistent failure. Digest-protected user-file replacement is unchanged. A separate fixture correction preserved root-level typed text when only its drawing group was erased.
7. **Empty scopes.** A root-only bridge cycle initially failed to persist its empty mapping. It now saves that mapping even when both scopes are empty. Trashed folders are excluded as virtual out-of-scope containers.

Earlier failed integration attempts are retained under their separate ignored `.test-tmp/zotero-publisher-live-09` through `-15` directories. Their passing prefixes are not counted as successful full runs. The final packaged-extension run is `-16`; the independent completed live-account run is `-11`.

## Handwriting finding

The real-source sample contained **zero saved handwriting transcripts** despite thousands of preserved Ink objects. Notable's ability to search saved OCR text must not be confused with having recognized these particular notes. That source-render test does not establish recognition accuracy. October 19's optional recognizer was evaluated on the separate synthetic paper with the user's new physical handwriting; it was not silently run over the production library. Printed OCR, saved-transcript fixtures and newly recognized real ink remain distinct evidence.
