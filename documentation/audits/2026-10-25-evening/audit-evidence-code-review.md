## Safety and evidence boundaries

- `backup_plugin.py:19-39` copies the database and sidecars, then performs SQLite recovery/integrity checking only on the copy. Its stopped-application prerequisite is operator-enforced. `43-53` intentionally excludes source/cache/runtime directories while privately copying configuration and DPAPI-protected grants. It is a filtered state/database backup, not proof that every raw PDF/layer file was copied.
- `verify_uploaded_cloud.py:35` uses the production `blobs` directory as a cache. Its remote operations do not modify cloud documents, but `CloudClient.blob` may touch cache timestamps, save metadata blobs, and prune disposable cached blobs. Its `cloud_read_only` label must not be interpreted as absence of all local writes. The fresh sample client at `50` has no cache and hashes only up to three small server blobs. All-file metadata digest comparisons are not all-file fresh byte downloads or proof of physical tablet synchronization.
- `verify_sync_state.py:30-56` reads SQLite through `mode=ro` into memory, omits upload-receipt contents from selected rows, and applies finite database/query deadlines. Its separate database snapshots are not a cross-database transaction. Its source-history checks explicitly distinguish a later tag revision from missing retained source data, and mark the known source-excluding backup accordingly. Only the expected matched original PDFs are byte-hashed. Capture/publication results remain journal and local-file evidence, not independent device evidence.
- `verify_sync_state.py:273-275` permits both output arguments under the audit or `.test-tmp` trees. Defaults keep private titles/identifiers in `.test-tmp`, but a caller can explicitly put the private `--details` file under the audit tree. Maintain the documented private-output location when invoking it. `diagnose_unlinked_pdfs.py` uses fixed private output for native keys/titles/paths, saved encrypted grants without interactive authorization, and read-only API/file checks; its changed-home observations are review context, while the separately established duplicate-baseline guard explains the three known skipped uploads.
- `packaged_status_smoke.py` creates only synthetic helper state below `.test-tmp` and exercises status/shutdown, not real library synchronization. The native PDF-diagnostic fixture gates its writes on a disposable fixture's `ready.json` server identity, uses synthetic item keys/PDF bytes, verifies source/stored bytes, and closes that fixture in `finally`; it has no cloud path. Those are deliberately mutating isolated fixtures, not readonly production probes.
- Historical `backend_repros.py` expects the original defects; it is not a current passing repair suite. `shared_repro.py` uses generated PPTX/PDF metadata and a mocked DOI resolver. `frontend-transport-noise-repro.cjs` runs the actual controller in a VM against a synthetic process. These establish controlled code behavior, not live tablet/application correctness.
- Several evidence drivers overwrite their default JSON/log result paths on rerun. Preserve versioned/attempt-specific copies before rerunning, as done for the packaged 0.8.6/0.8.7 results and the first native-PDF fixture attempt. Current source execution must not be presented as reproduction of a historical artifact unless the recorded dependency/helper/source hashes also match.
