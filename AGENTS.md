# Project instructions

## Look for existing open-source work first

Before implementing a new capability or substantially replacing an existing subsystem, research existing open-source projects, the libraries already used here, and relevant upstream APIs. Prefer a suitable existing component, supported integration, or small adaptation over recreating it.

For the selected candidates, check the actual capability, license, maintenance, Windows compatibility, and relevant application/device versions. Distinguish documented behavior from a repository claim or an untested idea. Record why reuse is appropriate or why a small custom implementation is still needed. This requirement does not call for a new internet survey for routine fixes or cosmetic edits.

Keep the user's research workflow and simplicity central. An integration that adds more recurring setup, duplicate files, or manual repair is not automatically an improvement.
